# JADEVEIL — A Voxel Realm of Mist and Jade

> 玉帷 · 云锁仙山，玉映朱阙
>
> A procedural pixel-art voxel sandbox built with three.js. Crimson walls, gilded roofs, lantern streets, cloud-wreathed floating isles — every texture drawn pixel by pixel in code, fully offline.

A Chinese-classical voxel sandbox built from scratch with three.js: crimson palace walls,
glazed gold roofs with upturned eaves, lantern-lit streets, mist-wrapped floating isles,
lotus ponds — plus 32 wandering NPCs.

**All textures are drawn pixel by pixel in code. No external image assets. Fully offline.**

## 一、启动方式

需要 Node.js（本机为 v24.11.0）。项目自带零依赖静态服务器：

```bash
export PATH="$HOME/.nvm/versions/node/v24.11.0/bin:/opt/homebrew/bin:$PATH"
cd ~/Projects/pandaria-voxel
node serve.mjs 8123
```

浏览器打开 <http://127.0.0.1:8123/>

> 必须通过 HTTP 打开，不能直接双击 `index.html`（ES Module + importmap 在 `file://` 下会被浏览器拦截）。

## 四、技术要点

### 1. 碰撞：子步进扫掠 AABB（无隧穿）
- 每帧位移拆成若干子步，**单步位移不超过 0.35 格**，从根本上消除高速下坠的隧穿。
- 每个子步内逐轴分离解算（X → Z → Y），避免斜向穿角。
- 碰撞解算先二分逼近，再从方块网格直接推导贴合面，保证玩家精确站在方块顶面（不悬空、不陷入）。
- **飞行与步行走同一套碰撞解算** —— 飞行分支只负责算速度，位移积分统一走 `moveWithCollision`。
- **世界顶部硬限位**：世界高度 160 格，玩家不得飞出体素体积（否则上方无碰撞体可挡）。
- 自动化测试 `tests/collision.test.mjs` 覆盖 **30 项断言**。

### 1.2 三个已修复的隐蔽缺陷（经验记录）

**缺陷 A：飞行悬浮**
- 现象：飞行中向下飞，玩家停在半空不再下落。
- 根因：飞行阻力把速度渐近衰减到 0，而飞行模式没有重力。
- 修复：无推进输入时保留最小滑行速度 `FLY_GLIDE_MIN`。

**缺陷 B：恰好落在顶面时不被识别为落地**
- 现象：落到方块顶面后直接穿下去。
- 根因：`collides()` 的 AABB 从脚底 `py` 开始，当 `py` 恰好等于方块顶面（整数）时，
  AABB 不包含下方那块实心方块，于是返回 `false` → `moveAxis` 提前返回 →
  `onGround` 未置位 → 玩家继续下落穿透。
- 逐帧证据：`from 126.117 → to 126.000, vy=0, onGround=false`，下一帧继续下落到 125.867。
- 修复：新增 `hasSupportBelow()`，在垂直下落且 `collides()` 为 false 时，
  额外检查脚底正下方一格是否有支撑；有则贴齐到支撑面并置位 `onGround`。

**缺陷 C：空中的黄色块体可穿过（用户反馈「黄色砖块穿透」）**
- 现象：飞行时直接穿过空中的黄色块状物体。
- 根因：**宫灯（id 34，rgb 200,124,59 橙色块状）**、**云雾（id 37，天空中的大块云体）**、
  **石狮（id 33）** 三种方块的 `solid` 被设为 `false`（当作纯装饰），
  因此碰撞查询直接跳过它们。
- 验证：随机游走 + 飞行探针（12000 帧）确认玩家**从未**进入任何实心方块内部，
  说明不是碰撞失效，而是这些方块本身就没登记碰撞体。
- 修复：三种方块改为 `solid: true`，现在可以站在云雾与宫灯上。
- 副作用修复：`groundHeight()` 改为只统计**不透明**方块，
  避免出生点/NPC 路径/小地图把云层当成地面（新增 `topSolidHeight()` 取任意实心最高点）。

**缺陷 D：测试模块语法错误导致整个应用无法启动**
- 根因：`tests/collision.test.mjs` 用模板字面量导出测试源码，内部又嵌套了 `${}`。
- 修复：导出时转义嵌套的 `${`，并在 Node 下验证模块与内部源码均可解析。

### 2. 飞行：带质量的飞行物理
- 推进力沿视线方向，**俯仰角影响速度矢量**（朝下飞会加速俯冲）。
- 线性 + 二次空气阻力，松开按键后**保留动量滑行**，不是瞬间停住。
- 退出飞行时垂直速度平滑衰减，交给重力接管，不是瞬间切换。

### 3. 程序化像素贴图（64×64 高分辨率像素风）
- 每种方块贴图是 **64×64 逐像素绘制**：`Bitmap` 类提供 `fill / rect / circle / speckle / bevel / outline / bricks` 等原语。
- 统一光照约定：光源在左上，所有贴图左上提亮、右下压暗。
- **方块变体**：16 种基础材质各生成 4 个随机变体（共 102 张贴图），按方块坐标哈希稳定选取，消除大面积重复感。
- 拼进图集时每个 tile 四周留 **2px 边缘外扩**，配合 `NearestFilter` + 关闭 mipmap，彻底消除接缝与渗色。

### 3.1 美术路线（详见 `docs/ART_DIRECTION.md`）

调研潘达利亚官方美术设定后，选择 **「体素地形 + 精细构件 + 高分辨率像素贴图」混合路线**：

| 维度 | 纯体素 32×32 | 本作（混合 + 64×64） |
| --- | --- | --- |
| 贴图细节 | 32×32 | **64×64**（4 倍像素信息） |
| 重复感 | 同材质完全一致 | **4 变体随机分布** |
| 氛围 | 静态 | **花瓣/竹叶粒子、香炉烟、灯笼摇摆** |

**为什么不用更小的体素**：体素单位降到 0.25 格，方块数变 64 倍，当前 78 万三角面会变成 5000 万，不可行；且更小的方块仍是方块，曲线依然靠阶梯近似。
**为什么不用写实渲染**：用户要求「仍然是像素风」。

本路线接近「高分辨率像素艺术」（如《八方旅人》HD-2D），而非写实渲染。

### 4. 体素网格与 AO
- 只生成暴露面（邻块不透明则剔除）。
- **逐顶点 AO**：3 邻域算法计算 0–3 级遮蔽，并依据 AO 选择三角剖分方向，避免折痕。
- 面朝向明暗烘焙进顶点色。

### 5. 水面着色器
- **三层 Gerstner 波**叠加（顶点位移 + 解析法线）。
- **菲涅尔反射**：视角越掠射反射越强。
- 深浅水颜色过渡、岸边泡沫、太阳高光随角度变化、水下视角色偏。

### 6. 光照与昼夜
- 方向光（太阳/月亮，`PCFSoftShadowMap`，阴影相机跟随玩家）+ 半球光 + 环境光 + 补光 + 夜间月光。
- 昼夜循环关键帧插值：太阳角度、天空色、雾色、光照强度、曝光、`night`/`warm` 通道。
- **黄金时刻**：太阳低角度时方向光偏橙红、建筑受光面泛金，暗部补冷色拉开冷暖对比。
- **夜晚**：抬高曝光 + 暗部抬升为冷靛蓝（避免死黑）+ 暖色高光溢出。

### 7. 灯笼发光
- 灯笼方块带 `aEmissive` 顶点属性，自发光强度由 `uEmissiveBoost` uniform 随昼夜曲线驱动。
- 每个灯笼位置额外放一个**高亮自发光光核**（InstancedMesh），给 bloom 明确的溢光源。
- 玩家附近最多 8 盏灯笼启用真实点光源（数量预算），其余靠自发光 + bloom。

### 8. NPC 系统
- **32 个 NPC**，6 种职业：守卫 / 商贩 / 僧人 / 孩童 / 武僧 / 长者，各有配色与体型。
- **行走动画**：腿部与手臂交替摆动（正弦驱动），身体轻微起伏。
- **路径巡逻**：沿规划路径点行走，到达后平滑转向下一个点，并贴地跟随地形高度。
- **状态机**：巡逻 → 驻足 → 交谈 → 招手 → 回到巡逻。
- 用 **InstancedMesh 分部件渲染**（头/身/双臂/双腿/帽），7 个 draw call 渲染全部 NPC。

### 9. 主城规划
放弃随机散布，改为有规划的中轴对称布局：
**南城门 → 牌坊 → 灯笼长街（坊市）→ 中央广场（水池/曲桥）→ 主殿 → 后苑（塔林/竹林）**
- 建筑细节：斗拱、窗棂、柱础、台阶、梁枋彩画、屋脊走兽、匾额。
- 生活化道具：摊位、酒旗、水井、花坛、拴马桩、石灯。
- 屋顶天际线高低错落（坊市 6–8 格、配殿、宝塔 4–6 层）。

### 9.1 浮岛登岛石阶（可达性设计）

**问题**：浮岛下方挂着 12–13 格厚的实心倒锥（山岩/墨石），从下方飞上去会被锥体挡住，
玩家无法登岛。这不是碰撞 bug —— 碰撞正确工作，是**关卡设计缺少登岛路径**。

**方案**：为每座浮岛建一条**螺旋上升的浮空石阶**：
- 从浮岛外侧地面起步，绕岛盘旋而上，每级升 1 格（可直接走上去，无需跳跃）
- 青石板铺面 + 苔石支撑层，两侧石灯（发光，夜景可见）+ 白玉栏杆
- 顶部平台与岛顶同高，并铺一条无障碍连接桥通往岛心
- 石阶半径保持较宽（≥ 岛半径 + 4），避免上下层在垂直方向堆叠成墙

同时清理浮岛周围**孤立的屋顶碎片**（下方 6 格全空、上方也空的悬空方块），
它们会挡住飞行路线。

**验收测试**：`tests/island-access.test.mjs` —— 模拟真实操作路径
（从地面起飞 → 飞行上升 → 横移 → 降落），穷举 6 座浮岛，
断言 `onGround === true` 且 `y === 岛顶高度`。

**当前结果：6 / 6 通过。**

### 10. 环境粒子与动态细节
- **飘落花瓣 / 竹叶**：900 个粒子，顶点着色器驱动飘摆与旋转，跟随玩家。
- **香炉烟雾**：14 个灯笼位置各 22 个粒子，缓慢上升扩散。
- **灯笼摇摆**：光核 InstancedMesh 矩阵按正弦轻微摆动，营造风吹感。
- 全部用 Points + 顶点着色器，无每帧对象分配。

### 10.1 全像素风界面系统（`src/ui/pixelui.js`）

整个 UI（启动页、加载页、所有面板、按钮、快捷栏、滑块、开关、小地图框）
统一为**逐像素绘制的像素画风格**：

- 所有纹理用 **Canvas 逐像素生成 → dataURL**，零外链资源，离线可用
- **9-slice 边框**（`border-image`）+ 平铺底纹（`background-repeat`），拉伸不变形
- 硬边、**无圆角、无模糊、无平滑渐变**；四角为**台阶式切角**
- 面板四角加**回纹拐角**装饰
- **扫描线叠加层**，强化像素屏幕质感
- **真像素字体**：标题文字先渲染到低分辨率 canvas，再整数倍放大，
  每个像素变成 N×N 方块（`pixelTitle()`）
- 配色：墨底 `#14181c` / 琉璃金 `#e8b44a` / 朱红 `#c0392b` / 青玉 `#4a9e8f`


### 10.2 全英文像素界面

界面文字**全部为英文**，由 `src/ui/pixelfont.js` 的 **5×7 位图像素字体**绘制
（字符以字符串点阵定义，整数倍放大，保证落在像素网格上不糊）。
支持描边与硬投影，字号分 1/2/3/4/5/6 档，标题用大号描边字。

覆盖：加载页、启动页、暂停页、状态面板、时间面板、设置面板、快捷栏、
小地图标注、操作提示、方块名称、错误提示。

**零中文校验**：`grep` 全量源码 + 遍历 DOM `textContent`，两处均为 0。

### 10.3 命名

项目定名 **JADEVEIL**（玉帷）—— 取「玉」与「帷」二意象：
青玉是主色调，云雾如帷幕笼罩仙山。副标题 *A Voxel Realm of Mist and Jade*。

候选方案：
| 名称 | 中文意象 | 理由 |
| --- | --- | --- |
| **JADEVEIL** | 玉帷 | 青玉 + 云雾如帷，覆盖两大视觉母题；古典且原创 |
| CINNABAR GATE | 朱阙 | 朱红宫阙，指向建筑而非氛围 |
| CLOUDSPIRE | 云岑 | 云雾山巅与塔尖，偏地理感 |

选定 **JADEVEIL**：最能概括「朱墙金瓦 + 云雾仙山 + 青玉」的整体气质。

### 11. 后处理
`RenderPass → UnrealBloomPass → 色彩分级（暗角 + 饱和度 + 对比度 + 冷暖分离）→ OutputPass`
色调映射 `ACESFilmicToneMapping`，bloom 阈值保持较高，只让灯笼、金瓦、水面高光溢出。

| 中 | 6 区块 | 130 | — | — |
| 高（默认） | 7 区块 | 170 | **418** | 929k |
| 极致 | 9 区块 | 230 | **447** | 931k |

**优化手段**：区块网格合并（每区块一个 geometry）、距离剔除（每 6 帧更新可见性）、视锥剔除、贴图图集单次绑定、InstancedMesh 用于灯笼光核与 NPC、对象池复用（矩阵/向量）。

**渲染耗时**：2.1 ms/帧，实测无控制台报错。

> 注：在 ego-browser 窗口中测得 30 fps 是浏览器窗口的帧率上限，非性能瓶颈 —— 空转 rAF（不渲染任何东西）也只有 40 fps，而实际渲染仅 0.67 ms。

### Batch 2 — 水面平面反射

- **真实平面反射**：镜像相机把场景渲染到 RT，水面着色器按世界坐标采样，
  建筑与天空真实倒映（不再是着色器近似）
- 用法线扰动 UV，倒影随波起伏
- **水下焦散**：FBM 波纹聚光，水面与水下均可见
- **深度吸收**：按真实水深做 `mix(shallow, deep, depth*1.6)`，越深越暗越偏青
- **海岸泡沫**：只在浅水出现（`smoothstep(3.5, 0.15, depth)`）
- **水下体积雾**：`exp(-sub*0.03)` 随深度衰减 + 色偏

- 反射渲染在 0.5 倍分辨率，帧耗时 0.7ms → 1.46ms（仍远低于 16.7ms 预算）


### Batch 3 — 材质质感：先做通道，再做分辨率

**技术判断**：单纯把 64×64 提到 128×128，像素量翻倍但观感提升有限
（玩家在正常距离根本数不出像素）。**增加材质通道的性价比远高于提分辨率**，
因此先做法线图 + 粗糙度图，分辨率留作后续按需处理。

- **法线图**：从颜色贴图的亮度当高度场，3×3 均值去噪后 Sobel 求梯度，
  转成切线空间法线。砖缝凹陷、石面颗粒、瓦楞起伏都会产生真实凹凸感。
  与颜色图共用同一张图集布局，因此 **UV 自动对齐**，无需第二套 UV。
- **粗糙度图**：按材质语义逐 tile 写入不同粗糙度，拉开「手感」差距：

| 材质 | roughness | 效果 |
| --- | --- | --- |
| 琉璃金瓦 / 金砖 / 夜明珠 / 匾额 | 0.20 | 强镜面、窄高光 |
| 青玉 | 0.32 | 半光泽 |
| 汉白玉 / 栏杆 | 0.48 | 微亮 |
| 木梁 / 竹竿 | 0.66 | 中等 |
| 朱红宫墙 / 立柱 / 彩画 | 0.86 | 漫反射 |
| 石板 / 山岩 / 苔石 / 土 / 草 | 0.94 | 粗糙 |

- 材质 `metalness` 提到 0.10（基础介电质），琉璃与金瓦靠**低粗糙度**出高光，
  而不是靠金属度，避免整体发黑。
- 两张附加图与颜色图同为 `<NearestFilter>` + 关闭 mipmap + `NoColorSpace`（数据贴图），
  不会因色彩空间转换而失真。

**性能**：帧耗时 1.46ms → 0.95ms（法线/粗糙度是单次采样，开销低于反射）。


### Batch 4 — 光照与氛围

- **体积光（god rays）**：新增 24 次径向采样的后处理 pass。
  只让亮度超过阈值的像素（天空、金瓦高光）产生光束，因此是「阳光穿过屋檐」而不是全局泛白。
  太阳投影到屏幕外时自动关闭；黄金时刻强度拉满（`0.30 + warm*0.75`），夜晚降到近乎 0。

**性能（含所有批次）**：0.8–1.5 ms/帧，绘制调用 110–722（视画角而定）。

## 十三、水体与游泳

### 修复：潜水时水面消失

`renderer.renderReflection()` 里为了「水下不渲染反射」而提前返回，
但顺手把整个水面材质也隐藏了：

```js
if (cam.position.y < L - 1) {
  this.matWater.visible = false;   // 隐藏了整个水面网格
  return;                          // 而且再也没有恢复
}
```

唯一恢复它的代码在反射渲染的末尾 —— 正是被跳过的那个分支。
于是人在水下时，水面每帧都被隐藏，抬头只能看见天空和城市（实测 `matWater.visible === false`）。

现在：反射逻辑只管反射，水面可见性与之解耦。

### 水面从下方看的样子

新增 `uUnderwater`，从水下看水面按真实光学模型着色：

| 视线角度 | 现象 |
| --- | --- |
| 接近垂直向上 | **斯涅尔窗** —— 水面外的天空/太阳透射进来，很亮 |
| 掠射角 | **全内反射** —— 光出不去，只看到水体自身的暗青绿 |

用 `smoothstep(dot(N,-V))` 混合，另加波峰高光，水面从下方看依然有起伏。

### 水下氛围

- 场景雾整体染成水体色（浅 `#2c6d78` → 深 `#0b2f3a`），雾距从 0.0062 拉到 0.011–0.029
- 按深度吸收，越深可见度越低；曝光压低 10%
- 进出水用阻尼过渡，不会瞬间变色

### 焦散（水面波纹聚焦的阳光）

注入到不透明/镂空材质着色器里，**只看片元是否在水面以下**，与相机位置无关 ——
所以从岸上看水里，湖底的那张亮网也是同一个效果。

- 双层干涉图案，与水面波纹同步
- 夜间随 `st.night` 衰减
- 颜色取太阳色与青色插值（阳光穿过水体后长波先被吸收）

**调试记录**：初版把 `1.0/length(...)` 的中间量直接送进 `pow`，
`inten` 很小时会除零得到 Inf，整屏爆成纯白。现在对中间量与返回值都做了夹紧。

**验证方式（对照组）**：同一机位拍两张，只切换焦散强度 0 / 1，
并冻结动画时间，逐像素比对：

| 机位 | 差异像素 | 平均通道差 | 平均亮度 |
| --- | --- | --- | --- |
| 看向城市（水面之上） | 1% | 1.2 | 30 → 29 |
| 水下俯视水底 | 97% | 25.5 | 42 → 66 |

对照组几乎无差异，证明焦散严格作用在水下片元上。

### 水中悬浮微粒

`WaterMotes`：以相机为中心循环平铺的「海洋雪」，缓慢下沉并横向摆动。
只在相机入水时淡入，出水即隐。微粒在世界空间静止，不会跟着视角漂。

## 十二、世界底与虚空保护（修复「挖穿后无限下坠」）

### 根因

两个问题叠加：

1. **地形填充深度不足**：`generateTerrain()` 旧版只填地表以下 14 格，
   于是 **y = 0–19 是空的**。玩家一路挖下去就会掉出世界。
2. **旧的重生逻辑会形成死循环**：掉到 `y < -8` 时，旧代码把玩家瞬移到
   **同一个 x/z 的 y=70**。如果那里正是被挖穿的洞，玩家立刻再次下落 —— 无限循环。

### 修复 A：世界底基岩层

- 在 `y = 0–2` 铺满**不可破坏的基岩**，范围 ±176（比生成半径 168 更大一圈，避免边缘漏洞）。
- 地形填充改为**从基岩顶面（y=3）一直填到地表**，地层之下不再有任何空腔。
- 基岩在方块注册表中标记 `unbreakable: true`：
  - `breakBlock()` 直接拒绝破坏，并提示 `BEDROCK — CANNOT BREAK`
  - `placeBlock()` 拒绝覆盖
  - 选中描边改成冷蓝色、不再显示面高亮，一眼区分「这是世界底」
- 独立贴图：近黑岩体 + 交错裂纹 + 稀疏高光颗粒，与普通石材明显区分，
  并自动接入法线/粗糙度体系。

### 修复 B：虚空保护

- 新增 `findSafeSpawn()`：螺旋向外搜索**校验过的安全点** ——
  该列有不透明地面、脚部与头顶两格皆空。
- `respawn()`：落出世界时重生到安全点（不再是固定 y=70），
  并触发**淡出→重生→淡入**的画面反馈与 `RETURNED FROM THE VOID` 提示。
- 出生点也改用 `findSafeSpawn()`，因此**新会话开场必定落在安全位置**。
- 阈值 `VOID_Y = -1`；任何时刻都不可能无限下坠。

### 顺带的性能修复

基岩层 + 全深度地形填充让写入量从约 120 万涨到约 **477 万方块**，
启动时间一度飙到 **74 秒**。原因是 `world.set()` 每次都要
`key(cx,cz)` 拼字符串 + 维护脏区块集合。

改为：
- 区块键从字符串改为**数字键**（`VoxelWorld.key/decode`）
- 新增 `setRaw()` / `fillColumnRaw()`，生成阶段不做逐格脏标记，
  生成结束后统一 `markAllDirty()`

**启动时间 74s → 28s**，帧耗时 0.58ms。

## 十五、体验打磨（脚步节奏与 NPC 智能）

### 脚步音效节奏

旧版用 `horizSpeed * dt * 1.9` 累加、阈值 1 触发，导致每秒约 9 步，像机关枪。
现在按**走过的距离**触发：步行约每 2.1 格一步、冲刺约每 2.6 格一步，步频和
真实行走节奏一致。

### NPC 智能（工业级状态机 + 物理）

旧版 NPC 只做「沿路径采样地面高度」，没有碰撞，会穿墙、上房顶、飘着走。

重写后：

- **真实物理**：重力 + 轴分离 AABB 碰撞（与玩家同款判定），不穿墙、不悬空、
  可下台阶；落地精确贴地。
- **有限状态机**：`patrol`（沿路径）→ `idle`（驻足）→ `wander`（游荡，撞墙自动
  换方向）→ `greet`（玩家靠近时打招呼）。
- **打招呼**：玩家进入 4.2 格范围时，NPC 停下、转身面向玩家、招手，并在头顶
  弹出**像素字气泡**（深色圆角底 + 金边，按角色说不同的话：守卫 / 商人 / 武僧 /
  孩童 / 武僧斗士 / 长者）；冷却 8 秒，不会反复打扰。
- 渲染仍是 InstancedMesh 分部件（身体/头/四肢/帽），零额外 draw call 压力。

验证：32 个 NPC 无一人穿墙（insideSolid=0）、全部贴地（32/32）、玩家靠近时
